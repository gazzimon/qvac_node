The problem

Today, "using AI" means sending your prompt to somebody else’s machine.

Every request to a large model travels to a datacenter you don’t control, at a per-token cost somebody else sets, in a queue whose length depends on how many other people are asking for it right then.

If that provider goes down, raises the price or changes the terms, there is no plan B — your product depends on a single company, in a single place.

Meanwhile, most machines on the planet with a GPU or a decent CPU sit powered on and idle for most of the day.

The idea

The Airbnb of AI compute — every node is both buyer and seller.

There is no PyrusLLM server in the middle. Every machine that installs the CLI runs its own model, signs a manifest and announces it on a Hyperswarm topic. A gateway compatible with the OpenAI API routes each request to the node it belongs to — yours, or another operator’s on the network — and records what was consumed to settle it in batches in $QVAC.

The app

It opens on a chat. The network is what answers.

Your node starts switched off, and the first thing you see is a single button. Launching it puts your machine on the network — and that is what gets you access to everyone else’s. Until then your own model still answers; the network does not.

Trust

Whatever decides and charges cannot belong to anyone.

An inference market has a blind spot: someone has to match every request with a node, and in doing so sees both ends — who is asking and who is answering. Someone has to count consumption and decide how much each provider charges. That someone can reconstruct the whole network’s activity and controls the money. Encrypting the traffic does not prevent it: it needs to read both sides in order to work.

That is why that layer runs inside a confidential execution environment. We are not promising not to look: we cannot, and with the enclave code published anyone can verify it. What is still outside it we say anyway — while answering, the node reads the prompt in plaintext; closing that last leg takes confidential GPU, and that is the next step.

Why it is real

Genuinely compatible, not a demo wearing an API’s name.

/v1/models and /v1/chat/completions follow the OpenAI format to the letter — any existing client hits them without a single line changed. What belongs to the marketplace (price, operator, load) lives apart, in /v1/nodes, so the protocol stays clean.

The economics

A cheap machine can pay for itself faster than an expensive one.

Payback is capital divided by the tokens you actually produce — so the question is never "how fast is this hardware", it is "how many hours a day is it producing tokens somebody values". Put two machines side by side and see for yourself. Every assumption below is editable.

Every cell is the same machine and the same model — only how busy it is and what its tokens are worth change. That spread is the whole business.

How this is computed. Generating a token reads the whole model out of memory once, so throughput is bounded by memory bandwidth: tok/s ≈ bandwidth × 75% ÷ model size. These are physical-limit estimates, not measurements on the machines, and bandwidth figures come from each machine's memory spec. Prices are list, with no import duty added. Payback is capital ÷ monthly net; NPV discounts 36 months at 12% a year.

Get started

One line, and your machine is part of the network.

No account, no runtime to install first. The download is a single self-contained binary with the inference engine inside — no Node, no npm, no Pear. It opens in your browser and waits there; no model is downloaded until you send the first prompt.

Already running Node, or want automatic P2P updates? Install over Pear instead:

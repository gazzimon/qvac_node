The problem

Today, "using AI" means sending your prompt to somebody else’s machine.

Every request travels to a datacenter you don’t control, at a price somebody else sets, in a queue as long as everyone else’s demand that second.

If that provider goes down or changes the terms, there is no plan B — one company, in one place.

Meanwhile, most machines with a GPU or a decent CPU sit powered on and idle for most of the day.

What it is

The Airbnb of AI compute — or, for anyone who knows the space, a peer-to-peer OpenRouter.

There is no PyrusLLM server in the middle. Every machine that installs the CLI runs its own model, signs a manifest and announces it on a Hyperswarm topic. Each node is both buyer and seller.

A gateway compatible with the OpenAI API routes each request to the node it belongs to — yours, or another operator’s on the network — and records what was consumed so it can be settled in batches.

The app

It opens on a chat. The network is what answers.

Your node starts switched off, and the first thing you see is a single button. Launching it puts your machine on the network — and that is what gets you access to everyone else’s. Until then your own model still answers; the network does not.

What we can and can’t promise

The honest version of the trust story.

An inference market has a blind spot: whatever matches a request to a node sees both ends, and whatever meters consumption controls the money. That layer runs so that no corporation aggregates your data at scale — but we won’t oversell it. While it answers, the node reads your prompt in plaintext.

Closing that last leg takes confidential inference. The compute overhead is now measured at 4–8% (arXiv:2509.18886), and its limits are known: memory and the interconnect stay unencrypted, and timing still leaks structure. It is the next step, not a shipped feature.

Model substitution is detectable and on the roadmap (phase 10.5). Quantization is not — nobody has a reliable detector (arXiv:2504.04715) — so it is covered the economic way: a signed declaration, a stake, and arbitration, the role DeServe (arXiv:2501.14784) gives to optimistic verification. Economic, not technical, and we say so.

Genuinely compatible, not a demo wearing an API’s name.

Payments

Paid in the request path, in a stablecoin.

A request without a credential comes back 402, with an accepts[] array built from the provider’s signed manifest. The payee is the provider — never the gateway. Payment is verified synchronously, before the first token.

Why a stablecoin and not a token: the rail is USDT0, so a user is never exposed to the volatility of a project token. A native token, if there is one, lives in the incentive layer — future work.

Proof is a signed attestation next to the receipt: /node recomputes the output hash in the browser and checks it against the node’s manifest key.

402 → receipt + attestation
{
  "receipt": {
    "scheme":  "exact",
    "network": "usdt0",
    "payTo":   "0x9a…c1",   // provider address, from the signed manifest
    "value":   "1875",      // 6-decimal USDT0 units — 0.001875
    "auth":    "EIP-3009 transferWithAuthorization"
  },
  "attestation": {
    "model":      "llama-3.1-8b-q4",
    "tokensOut":  375,
    "outputHash": "blake2b-256:9c1d…7af2",  // over the JCS-canonical body
    "sig":        "ed25519:6b…09"           // node manifest key
  }
}

Caveat: today, P2P and local requests cost zero, and nothing has launched on mainnet. The verifiable artifact is the signed EIP-3009 receipt and the attestation — not an on-chain transaction hash.

Get started

One line, and your machine is part of the network.

No account, no runtime to install first. The download is a single self-contained binary with the inference engine inside — no Node, no npm, no Pear. It opens in your browser and waits there; no model is downloaded until you send the first prompt.

Already running Node, or want automatic P2P updates? Install over Pear instead:

npm i -g pear && pear install pear://8f789f6hsf4ghymku5eqwqmbqiubiigp8xpy6boiymunnbyznpny

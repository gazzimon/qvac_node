Reglas, en orden de importancia:

1. NO arregles codigo. Este es un pase de QA, no de desarrollo. Si algo falla,
   documentalo y segui con el test siguiente. Nada de editar archivos del repo
   salvo que yo te lo pida explicitamente.
2. Corre los tests EN ORDEN. Varios dependen del estado que deja el anterior
   (nodo levantado, api key emitida, par descubierto, wallet creada).
3. Para cada test devolveme, sin adornos:
   - el ID (T0x) y el veredicto: PASA / FALLA / BLOQUEADO / NO APLICA
   - el comando exacto que corriste (si lo adaptaste, deci por que)
   - la salida REAL pegada, recortada a lo relevante (no la resumas: el
     veredicto se lee de la salida, no de tu opinion)
   - los numeros que el test pide medir (segundos, tokens/s, TTFT, micros,
     codigo HTTP)
4. Un test PASA solo si se cumple TODO lo que dice "Resultado esperado". Si se
   cumple parcialmente es FALLA, con la parte que fallo escrita.
5. BLOQUEADO es cuando no lo pudiste correr (falta la maquina B, falta una
   credencial de proveedor, no hay red). Deci que falto.
6. Antes de arrancar, ejecuta el bloque "Preparacion" y confirmame el entorno:
   SO, version del binario (pyrusllm --version), directorio de storage, si hay
   .env y que variables cargo, si hay upstreams.json, y si hay un proceso viejo
   escuchando en 8787.
7. Nunca imprimas el VALOR de una API key, de una credencial de proveedor ni de
   PYRUS_WALLET_PASSPHRASE, y NUNCA las 24 palabras de la wallet. Los nombres de
   las variables si, los valores no. Si una salida los trae, enmascaralos con
   ****. Si un test te pide buscar la frase dentro de un archivo, reporta
   solamente si aparece o no, nunca el contenido.
8. Los comandos de la maquina B van marcados. No los corras en A "para
   simular": un test de dos maquinas corrido en una sola es BLOQUEADO.
9. Los tests que dicen "contra la suite" se verifican corriendo npm test y
   leyendo la linea del test nombrado. Pegame esa linea, no todo el output.

Preparación

Se prueba la instalación real: el binario que baja un usuario, no node bin.mjs desde el repo. El repo hace falta solo para scripts/ y las suites de test.

  • Máquina A — la que corre el pase completo. Windows 11 o macOS/Linux.
  • Máquina B — segunda máquina, en otra red o en el mismo hotspot. Alcanza con que corra pyrusllm serve --swarm.
  • Red — si el P2P no descubre pares, sospechar de la red antes que del código: un AP corporativo que bloquea UDP rompe el hole-punching. Plan B: hotspot del teléfono en las dos máquinas.
  • Nada escuchando en 8787 — un gateway viejo abierto es el error más probable de todo el pase.
  • Credenciales de proveedor — los tests de Fase 8 y 8.5 (T30 a T36) piden al menos una API key de NVIDIA o de OpenRouter en el .env. Sin ninguna, ese bloque entero queda BLOQUEADO, no FALLA.
  • Passphrase de wallet — PYRUS_WALLET_PASSPHRASE en el .env, larga y única. Sin ella no se puede crear ni abrir la wallet de la Fase 7.
Storage y config · dónde mira el nodo 
# El directorio de storage lo imprime el nodo al arrancar. Ahi viven:
#   identity.json     la semilla de red (en claro, declarado)
#   apikeys.json      las credenciales emitidas (persisten)
#   wallet.json       el keystore CIFRADO de la wallet de cobro (Fase 7)
#   upstreams.json    que proveedores externos usa este nodo (Fases 8 y 8.5)
#   ledger            el gasto del mes (persiste)

# Copiar la plantilla de upstreams al storage, y editarla ahi:
Copy-Item upstreams.example.json "\upstreams.json"      # PowerShell
cp upstreams.example.json "/upstreams.json"             # bash

# La credencial NO va en ese archivo: va el NOMBRE de la variable de entorno
# (campo apiKeyEnv), y el valor va en el .env. Es la razon por la que el
# secreto no entra al manifiesto firmado que se anuncia a la red.
Máquina A · PowerShell 
git clone https://github.com/gazzimon/qvac_node.git; cd qvac_node
npm install                      # solo para scripts/ y las suites
Get-NetTCPConnection -LocalPort 8787 -ErrorAction SilentlyContinue   # tiene que dar vacio
Get-Process bare,pyrusllm -ErrorAction SilentlyContinue              # procesos viejos: matarlos
Copy-Item .env.example .env      # y completar las claves que se vayan a usar
Máquina A · bash (macOS / Linux) 
git clone https://github.com/gazzimon/qvac_node.git && cd qvac_node
npm install
lsof -i :8787 || echo "8787 libre"
pgrep -fl "bare|pyrusllm" || echo "sin procesos viejos"
cp .env.example .env
El pase entero asume el puerto 8787. Si hace falta otro, cambiarlo en todos los comandos con --port y en las URLs, y anotarlo en el reporte.
